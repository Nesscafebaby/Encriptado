El cuaderno de al-Kindī

Cifra y descifra oraciones con César o Atbash sobre el alfabeto que tú definas.

1 · Alfabeto de trabajo (base: código ASCII)

El programa usa el código ASCII/Unicode de cada símbolo como base del módulo de cifrado: cada carácter del alfabeto es, internamente, un número de código, y desplazar (César) o invertir (Atbash) es aritmética sobre esos números. Por defecto se genera el rango ASCII imprimible 32–126 (95 símbolos: letras, dígitos, espacio y signos de puntuación), pero puedes generar cualquier otro rango de código —incluso fuera de la tabla ASCII de 128 posiciones— o escribir tus propios símbolos a mano.

a
32–126 = ASCII imprimible estándar (95 símbolos). 0–127 = tabla ASCII completa. Cualquier valor mayor a 127 sale de ASCII y entra a Unicode extendido (tildes, Ñ, símbolos, emojis…).

¿Cómo decide el programa cuál es la respuesta correcta, sin preguntarte a ti?

Un cifrado César o Atbash reemplaza cada símbolo SIEMPRE por el mismo símbolo. Eso significa que, aunque el texto se vea irreconocible, la "forma" estadística del idioma sigue intacta debajo del disfraz: en español, por ejemplo, la letra E aparece muchísimo más que la Z, y esa desproporción sobrevive al cifrado, solo que reetiquetada.

al-Kindī fue el primero en documentar cómo explotar esto: si conoces qué tan seguido aparece cada letra en un idioma, puedes comparar esa tabla contra cualquier texto cifrado y encontrar la clave que mejor "cuadra" con el idioma real, sin haber visto nunca la clave.

Este programa genera todos los descifrados posibles (Atbash + cada clave de César), probando a la vez la hipótesis de que el texto es español y de que es inglés, y les aplica una prueba estadística (ji-cuadrada, normalizada por la cantidad de letras reconocidas) contra la tabla de frecuencias correspondiente. También aprovecha que el carácter más común de un texto real no es una letra, sino el espacio entre palabras: esa señal por sí sola ayuda mucho incluso con oraciones cortas. El programa se queda con el candidato cuyo error estadístico es menor: esa es, con altísima probabilidad, la única respuesta correcta — y es la única que se muestra.

Hay dos límites honestos, y el programa los reconoce en vez de inventar una respuesta: si defines un alfabeto de símbolos que no corresponde a ningún idioma conocido (solo emojis, solo dígitos…), no existe tabla de frecuencias contra la cual comparar; y si el texto cifrado es demasiado corto (una o dos palabras), no hay suficiente muestra estadística para decidir con confianza. Ambas son limitaciones reales del propio método de al-Kindī, no fallas del programa.
